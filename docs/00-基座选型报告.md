# 阶段 A — 基座选型报告

> 目标：最大化复用开源截图 / 标注基座，只新增「挖空工具」和「Anki 保存链路」。
> 结论：**选用 `mysphinx-snip` 0.0.1（Python + PySide6，MIT）**，vendored 到
> `src/ankisnip/base/`。

## 1. 候选对比

| 维度 | **mysphinx-snip 0.0.1** | ScreenPinKit | Snapmockit 1.5.0 |
|---|---|---|---|
| GUI 框架 | **PySide6**（任务书首选） | PyQt5 | PyQt6 |
| 许可证 | **MIT**（`PKG-INFO: License: MIT`，`pyproject.toml: license = {text="MIT"}`） | 仓库有 LICENSE 徽章；`raw .../main/LICENSE` 取回 404，**条款未核实** | **MIT**（2026 Doug Bower，已核到正文） |
| 获取方式 | PyPI sdist（**上游未公布仓库 URL**）→ 采用 vendored，不用 submodule | GitHub `InterwovenCode/ScreenPinKit` + PyPI | GitHub `dbower44022/snapmockit` + PyPI |
| 代码规模 | **≈1970 行**（8 个模块） | 大：OCR、插件市场、git submodule、`internal_deps` | 很大：9 份 PRD + 完整产品线，AppImage/Flatpak |
| 依赖 | PySide6、pynput（**2 个**） | PyQt5、`system_hotkey` fork、cv2/onnxruntime/shapely… | PyQt6 + 若干 |
| 是否实测运行 | ✅ 已安装并跑通自带单测 | ❌ 未实测 | ❌ 未实测 |
| 平台可靠性声明 | macOS / Windows 均有明确说明 | 主要面向 Windows | README 明确写：**Win/mac 采集后端"已写但未在这两台机器上测试"** |
| 挖空注入难度 | **低**：`Annotation` 基类 + `ToolType` 枚举 + `AnnotationStack`，加一个类即可 | 高：QGraphicsView 体系 + 插件系统 | 高：图层 / 项目文件 / .snagx 体系 |
| 结论 | ✅ **选用** | 备选（许可证待核 + 体量过大） | 备选（Win/mac 采集未验证，风险最高） |

### 为什么不选另外两个

* **Snapmockit**：功能最全，但 README 自述 "The Windows and macOS capture backends are
  written but **have not yet been tested** on those machines"。本任务的两个目标平台恰恰
  就是 Win/mac，采集正确性无法假设；且它是完整产品（图层 / 项目文件 / SnagIt 兼容），
  要在这里面插入"不参与栅格化的标注"代价很高。
* **ScreenPinKit**：PyQt5（任务书要求跟随基座时可接受），但它把 OCR、插件市场、
  `internal_deps`、`system_hotkey` fork 都绑进来了，PyInstaller 打包体积与排障成本陡增；
  且许可证正文未核到，不适合直接 vendored。

### 运行验证中的两个发现

1. 基座自带单测在 `offscreen` 下 `test_draw_all_renders_without_error` 会
   `Fatal Python error: Aborted`。定位：测试里**没有创建 `QGuiApplication`**，
   `QPainter.drawText` 需要字体数据库。补一个会话级 `QGuiApplication` 夹具后
   **15 个用例全部通过**（已迁入 `tests/base/`）。
2. `QPixmap::toImage()` 的 dpr 语义在不同 Qt 版本下不完全一致，因此取选区图时
   不写死 dpr，而是用 `full.width() / widget.width()` **反推设备像素比例**
   （见 `overlay_ext.AnkiCaptureOverlay.selection_image`）。

## 3. 挖空工具注入点

基座 `annotations.py` 的设计几乎是为插件化准备的：

```python
class Annotation:                 # draw() / hit_test() / move() / bounding_rect() / is_valid()
class _TwoPointAnnotation(Annotation):   # 拖拽创建的两点图形
ToolType(str, Enum)               # 工具枚举
_TOOL_CLASSES: dict               # 拖拽型工具的工厂表
class AnnotationStack:            # 有序列表 + undo/redo + draw_all + hit_test
```

因此注入只动 **2 个文件、4 处**：

| 文件 | 改动 |
|---|---|
| `base/annotations.py` | ① `ToolType` 增加 `MASK = "mask"`；② 新增 `MaskAnnotation`（继承 `_TwoPointAnnotation`，半透明填充 + 虚线边框，`to_norm()`/`from_norm()`）；③ 注册进 `_TOOL_CLASSES`；④ `AnnotationStack.remove()` 供删除 |
| `base/toolbar.py` | `_TOOLS` 增加 `(ToolType.MASK, "▢", "挖空")`（编辑器工具条另起一份，见下） |

外加 `base/app.py` 两行钩子（`overlay_cls` / `config_cls`），让子类可以替换覆盖层与配置，
避免复制粘贴基座 40 行的 `start_capture()`。

**挖空之所以"不烧录进图片"的实现点**：`rasterize.split_annotations()` 按类型把
标注分成 `masks` / `baked`，`bake()` 只收到 `baked`。`MaskAnnotation` 类型本身即开关。

## 4. 图片栅格化导出接口评估

基座已有：

```python
# base/overlay.py
def compose(self) -> QPixmap:
    phys = QRect(sel.x()*dpr, sel.y()*dpr, sel.width()*dpr, sel.height()*dpr)
    result = self._pixmap.copy(phys)          # 物理像素 = 原图分辨率
    painter = QPainter(result)
    painter.translate(-sel.topLeft())
    self._stack.draw_all(painter, ctx)        # 含全部标注
    return result
```

评估：**思路可直接复用，但两处必须改造**，所以新增 `rasterize.bake()` 而不是直接调它：

1. 它画的是 `_stack` 里的**全部**标注 —— 需要先剔除 `mask`；
2. 它的输入是"覆盖层坐标 + 选区"，而编辑器的标注坐标系是"原图像素"，
   中间要过一道 dpr / 选区原点的换算，容易出错。编辑器直接持有原图 `QImage`，
   标注坐标就是原图像素坐标，烧录时 1:1 绘制即可，**完全没有 dpr 换算**。

`rasterize.bake()` 与基座 `compose()` 的对应关系：

| 基座 `compose()` | 本项目 `bake()` |
|---|---|
| `pixmap.copy(phys)` | `image.copy()`（编辑器拿到的就是原图） |
| `stack.draw_all()` | `for a in baked: a.draw(painter, ctx)` |
| `RenderContext(base_image=...)` | 同（马赛克需要采样底图） |
| — | **新增**：`split_annotations()` 先剔除 mask |

### 基座未覆盖、必须自研的部分（已在上面说明）

1. **缩放 / 平移编辑画布** —— 基座覆盖层没有视图变换，而验收第 3 条要求
   "400% 下挖空后缩回 100% 不变"。新增 `coords.py` + `editor_canvas.py`。
2. **挖空工具** —— 新增 `MaskAnnotation`（注入基座类型体系）。
3. **Anki 保存链路** —— 新增 `kong/` + `anki_connect.py` + `apkg_export.py` + `saver.py`。
4. **打包脚本** —— 基座没有，新增 `packaging/`。
