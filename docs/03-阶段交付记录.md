## 补丁 1 — 全局热键：原生注册优先 + 热键录制（用户反馈驱动）

**现象**

1. 全局快捷键在「点托盘图标」之外完全不触发。
2. 设置里的快捷键只能手输 pynput 记法（`<cmd>+<shift>+a`），用户不知道该写什么。

**根因**

上游 `SnipApp._install_hotkey` 只用 `pynput.GlobalHotKeys`。pynput 在 macOS 上
基于 `CGEventTap`，**必须授予「辅助功能」权限**；未授权时监听器静默收不到任何事件，
失败信息只 `print` 到 stderr（常驻托盘程序没有终端，用户永远看不到）。
本机实测 `AXIsProcessTrusted() == False`，现象完全吻合。

**改动文件**

| 文件 | 类型 | 说明 |
|---|---|---|
| `src/ankisnip/hotkey.py` | 新增 | 统一记法 → 平台原生注册（macOS Carbon `RegisterEventHotKey` / Win32 `RegisterHotKey`）→ pynput 兜底；`Hotkey` 数据模型、`GlobalHotkeyManager`（热重载）、`HotkeyStatus`（可读诊断） |
| `src/ankisnip/hotkey_capture.py` | 新增 | `HotkeyCaptureDialog`（按下即生成）、`HotkeyEdit`（只读显示 + 录制 / 清除）、`hotkey_from_qt_event` |
| `src/ankisnip/base/app.py` | 改基座（4 处） | `_install_hotkey` 换成管理器调用；上游实现保留为 `_install_hotkey_pynput`；新增 `reload_hotkey()` / `hotkey_status_text()`；菜单标签显示可读热键，失败时显式写「热键未生效」 |
| `src/ankisnip/app.py` | 改 | 托盘菜单「热键状态…」；设置保存后热重载（不再要求重启）；`_hotkey_suspended()`（可嵌套）在设置 / 录制期间挂起热键；首次运行提示改成按实际注册结果给出 |
| `src/ankisnip/settings_dialog.py` | 改 | 热键行换成 `HotkeyEdit`；`apply()` 取 `hotkey_edit.spec()` |
| `src/ankisnip/settings.py` | 改 | 默认热键改为复用 `hotkey.default_hotkey()`，去掉重复常量 |
| `tests/test_hotkey.py`、`tests/conftest.py` | 新增 | 记法解析 / 原生键码 / Qt 事件映射 / 后端选择与热重载，共 20 项 |
| `tools/hotkey_selftest.py` | 新增 | 真机自检（含人工按键模式） |
| `README.md`、`docs/01-变更说明.md` | 改 | 权限表、使用表、目录结构、验收第 1 项 |

**验证方式**

```bash
QT_QPA_PLATFORM=offscreen pytest -q        # 92 passed（新增 20 项热键用例）
python tools/hotkey_selftest.py            # 注册成功：macOS Carbon RegisterEventHotKey
```

* 已核对成熟实现 `QHotkey` 的 macOS 后端：同样是
  `InstallApplicationEventHandler` + `RegisterEventHotKey(GetApplicationEventTarget())`，
  本实现与其一致（含 `Qt::Control → controlKey`、`Qt::Meta → cmdKey` 的映射口径）。
* 本机 `AXIsProcessTrusted() == False` → pynput 路线确认不可用，Carbon 路线注册
  返回 `OSStatus 0`（成功）。

**遗留问题**

* **无法在本机自动验证端到端触发**：macOS 不把 `CGEventPost` 合成的事件投递给未
  获辅助功能权限的进程（对照实验：合成按键连前台 Qt 窗口都收不到）。因此
  `tools/hotkey_selftest.py` 提供人工模式 —— 运行后手动按一次组合键即可确认。
  建议用户在替换 `.app` 后按一次快捷键做最终验收。
* Carbon 事件依赖主线程 runloop（Qt 的 `app.exec()` 提供）。若将来改成分离线程
  跑事件循环，热键回调会失效。
* Win32 后端（`RegisterHotKey` + `QAbstractNativeEventFilter`）未实跑（无 Windows 机器），
  失败会自动回落 pynput，并在「热键状态…」里显示原因。

## 补丁 3 — 遮挡合成口径、离线目录失效、apkg 挖空不显示（用户反馈驱动）

**现象**

1. 复制 / 另存图片时，挖空遮挡没画进图（拿到的是没遮住的原图）。
2. 设置里改的离线导出目录不生效，文件还是落在 `/private/var/folders/...`。
3. 离线导出的 `.apkg` 导入 Anki 后矩形框不显示；同一张图走 AnkiConnect 直连就正常。

**根因**

* 第 1 项是设计口径没分场景：`compose()` 一律剔除挖空，只有「保存到 Anki」需要这样。
* 第 2 项是**我们的单测污染了用户真实配置**：`Settings()` 走
  `QSettings('ankisnip','anki-screen')` 真实域，`tests/test_saver.py` 的 fixture
  把 `offline_dir` 写成了 pytest 临时目录（`defaults read com.ankisnip.anki-screen`
  可直接看到 `/private/var/.../test_offline_apkg_fallback0/offline`）。
* 第 3 项：挖空矩形靠**笔记类型正面模板里内联的脚本**渲染（实测该模板 Front
  有 194103 字符、含 1 段 `<script>`、含 base32 字母表，完全自包含）。
  而 genanki 之前自建了一个只有 `{{pic_kong}}` 的空壳笔记类型，导入后
  Anki 按 model_id 匹配不上，就新建类型（用户 Anki 里已能看到
  `图片挖空模板sle1_0+` 这个垃圾类型），没有任何渲染脚本 → 矩形消失。

**改动文件**

| 文件 | 类型 | 说明 |
|---|---|---|
| `src/ankisnip/rasterize.py` | 改 | 新增 `bake_including_masks()`：复制/另存时把遮挡画成不透明块 |
| `src/ankisnip/overlay_ext.py` | 改 | `compose(include_masks=...)`；`_finish()` 按动作决定（`anki` 剔除，其余全部画进图） |
